# Страница выбора адреса Nordi

`dist/mirror/` — отдельная статическая страница перехода. Её следует
разместить на площадке, независимой от основного сайта, иначе при сбое
основной площадки страница тоже может оказаться недоступна.

Пока `dist/mirror/mirrors.json` содержит пустой список. Кнопка показывает
честное сообщение о том, что адреса готовятся. В бот эту ссылку пока не
добавлять.

Для первого выпуска достаточно одного купленного домена для основного сайта.
Страница выбора адреса и статическая запасная версия могут жить по публичному
HTTPS-адресу независимого хранилища, например Selectel S3. Адрес хранилища
не требует покупки второго домена, но само хранение и трафик тарифицируются.
До использования такого адреса проверить его с телефона без VPN. Для
независимости от сбоя Timeweb основной сайт и запасную копию размещать на
разных площадках. При недоступности хранилища в боте должна оставаться прямая
ссылка на основной сайт.

После покупки домена и публикации сайта:

1. Разместить `dist/` на основном HTTPS-адресе. Убедиться, что
   `/nordi-health.svg` открывается и возвращает изображение SVG.
2. Разместить статическую копию сайта на отдельном HTTPS-адресе и отдельной площадке.
   Проверить его без VPN с телефона.
3. Разместить `dist/mirror/` по отдельному адресу той же резервной площадки
   или по адресу третьей площадки. В
   `mirrors.json` записать два официальных HTTPS-адреса в порядке
   предпочтения, например:

   ```json
   {
     "mirrors": [
       { "url": "https://основной-адрес.example/" },
       { "url": "https://хранилище.example/бакет/" }
     ]
   }
   ```

   URL должен заканчиваться `/` либо указывать на `index.html`, чтобы
   проверка нашла `nordi-health.svg` рядом с главной страницей.
4. Проверить оба направления: при доступном основном адресе и при его
   недоступности. После проверки добавить ссылку страницы перехода в бот.

Проверка загружает маленькое изображение с каждого адреса с лимитом 4,5 с,
затем открывает первый ответивший адрес через 2 с. Доступность изображения
не доказывает исправность всех функций сайта: отдельно проверить страницу,
документы, поддержку, вход и платежи. Статическая копия не заменяет серверную
часть входа и платежей, поэтому её нужно обозначать как информационный
резерв, пока защищённый backend не развёрнут отдельно. На странице перехода не собираются
пароли и платёжные данные.

Политика конфиденциальности и пользовательское соглашение в футере пока
помечены как готовящиеся. Чужие документы из примера Atlanta не размещать
как документы Nordi.
